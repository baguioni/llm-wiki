# The Synergy of Speculative Decoding and Batching in Serving Large Language Models

Text source: arXiv HTML, version `2310.18813v1`.

## Summary

Auto-regressive generation produces one token per iteration, which gives low GPU utilization. [Batching](../methods/batching.md) and [speculative decoding](../methods/speculative-decoding.md) both raise utilization, so enabling one might offset the benefit of the other.[^suSynergySpeculativeDecoding2023] The paper implements a prototype of batched speculative decoding and profiles it across models, GPUs, batch sizes, and speculation lengths.[^suSynergySpeculativeDecoding2023]

The key observation is that the optimal speculation length depends on the batch size: larger batch sizes need a smaller speculation length, and a speculation length that is too large deteriorates performance.[^suSynergySpeculativeDecoding2023] The paper explains this with an analytical runtime model and proposes [adaptive speculative decoding](../methods/adaptive-speculation-length.md), which profiles briefly before deployment and then uses the optimal speculation length for each arriving batch.[^suSynergySpeculativeDecoding2023] For time-varying requests it reports an extra 9% latency reduction compared with a fixed speculation length.[^suSynergySpeculativeDecoding2023]

## Contributions

- A study of how batch size interacts with speculation length, with the observation that smaller speculation lengths need to be chosen for large batch sizes.[^suSynergySpeculativeDecoding2023]
- A quantitative model that explains the observation.[^suSynergySpeculativeDecoding2023]
- An adaptive speculative decoding strategy that chooses the optimal speculation length for each batch size.[^suSynergySpeculativeDecoding2023]
- An evaluation against schemes with fixed speculation length, showing equal or better performance.[^suSynergySpeculativeDecoding2023]

## Method

### Speculative decoding as used here

A Small Speculative Model (SSM) predicts $s$ subsequent tokens, and the LLM verifies them in parallel by computing the logits for each token. If a speculated token is not the highest-probability token, it and all later tokens are discarded. If $l$ tokens are correct, the sequence grows by $l+1$, because the LLM supplies either a correction or one look-ahead token. The algorithm uses argmax sampling.[^suSynergySpeculativeDecoding2023]

### Prototype

The prototype supports both optimizations for HuggingFace transformers models. Wrong speculation is corrected with attention masks: a token that fails verification and all tokens after it are masked off, and the LLM's correct token is appended to the sequence.[^suSynergySpeculativeDecoding2023]

### Runtime model

Notation: $N$ total tokens to generate, $b$ batch size, $s$ speculation length, $l(s)$ average number of correct tokens generated by the SSM, $t_L(b,s)$ per-step runtime of the LLM, $t_S(b,s)$ runtime of the SSM.[^suSynergySpeculativeDecoding2023]

- Total runtime: $T_{total}=T_L(b,s)+T_S(b,s)$ (Eq. 1), with $T_L(b,s)=\frac{N}{l(s)+1}\cdot t_L(b,s)$ (Eq. 2) and $T_S(b,s)=\frac{N}{l(s)+1}\cdot(s\cdot t_S(b,1))$ (Eq. 3).[^suSynergySpeculativeDecoding2023]
- The model covers only the auto-regression stage and neglects the prefilling stage. It assumes each iteration of the two models takes the same time.[^suSynergySpeculativeDecoding2023]
- $l(s)$ is measured empirically with $n=200$ prompts and $m=80$ SSM-generated tokens per prompt, as $l(s)\approx\frac{1}{n}\sum_{i=1}^{n}\min\{l_i,s\}$ (Eq. 4). It is fitted with a power function $l(s)\approx c\cdot s^{\gamma}$ (Eq. 5). The fitted approximation is $0.9s^{0.548}$. $l(s)$ is non-decreasing and sub-linear ($\gamma<1$).[^suSynergySpeculativeDecoding2023]
- $t_L(b,s)$, measured for OPT-6.7B on an RTX 3090, is approximately a step function. The first jump for $b=1$ is at $s=64$, while for $B=8$ it is at $s=8$. It is approximated as linear: $t_L(b,s)=\alpha_b s+\beta$.[^suSynergySpeculativeDecoding2023]
- Combined: $t\approx N\frac{\alpha_b\cdot s+\beta+t_S(b,1)\cdot s}{c\cdot s^{\gamma}+1}$ (Eq. 8). $t_S(b,1)$ is merged into $\alpha_b$.[^suSynergySpeculativeDecoding2023]
- Setting the derivative to zero, with $K=(1-\gamma)\cdot c$ and $L=c\cdot\beta\cdot\gamma$, the optimal speculation length $s_{opt}$ satisfies $K\alpha_b\cdot s^{\gamma}-Ls^{\gamma-1}+\alpha_b=0$ (Eq. 12). The left side increases with $b$ (through $\alpha_b$) and with $s$, so a larger $b$ requires a smaller $s_{opt}$.[^suSynergySpeculativeDecoding2023]

### Adaptive speculative decoding

- **Profiling stage.** A small sample of the dataset is used to measure latency under different batch sizes and speculation lengths. A grid search finds $s_{opt}$ per batch size, and the result is stored in a look-up table (LUT).[^suSynergySpeculativeDecoding2023]
- **Execution stage.** When a batch of requests arrives, the speculation length is read from the LUT.[^suSynergySpeculativeDecoding2023]
- **Search space.** The optimal speculation length is usually less than ten. Only batch sizes that are powers of two are profiled. For a batch size that is not profiled, the smaller speculation length of the nearest two profiled batch sizes is used.[^suSynergySpeculativeDecoding2023]
- **Overhead.** Profiling takes several minutes and is done once, before the service is launched.[^suSynergySpeculativeDecoding2023]

## Experiments & Results

### Characterization (Section 3.2)

Average latency per token was measured for batch sizes from 1 to 32 in powers of 2 and speculation lengths from 1 to 8, with OPT-1.3B, OPT-6.7B, and Llama-7B on RTX 3090, and OPT-6.7B on RTX 3090, RTX 4090, and A100.[^suSynergySpeculativeDecoding2023]

| Setting | Finding |
|---|---|
| RTX 3090, OPT-6.7B, batch size 4 | Speculation length 3 improves speed by $1.93\times$ |
| Batch size 1 | Speculative decoding reduces the per-token latency by up to 63% |
| Batch size 32 | The smallest per-token latency is achieved with a speculation length smaller or equal to 2 |
| RTX 3090, batch size 8 | Optimal speculation length is 3 for OPT-1.3B and 4 for OPT-6.7B |
| OPT-6.7B, batch size 4 | Optimal speculation length is 2 for A100 and 3 for RTX 4090 |

All rows: [^suSynergySpeculativeDecoding2023]

The full latency grids are given only in Figure 1 and are not reproduced here.

### Evaluation setup

- Dataset: the [Chatbot Instruction Prompts](../datasets/chatbot-instruction-prompts.md) dataset from Huggingface, prompt field only.[^suSynergySpeculativeDecoding2023]
- Hardware and software: NVIDIA RTX 3090, Ubuntu 22.04, CUDA 11.8, PyTorch 2.0.1.[^suSynergySpeculativeDecoding2023]
- Models: OPT-6.7B as the LLM and OPT-125M as the SSM.[^suSynergySpeculativeDecoding2023]

### Uniform traffic (fixed batch size)

1000 prompts are sampled and grouped into batches, with 128 new tokens generated per prompt. The metric is end-to-end time including the tokenizer, normalized to the baseline without speculative decoding.[^suSynergySpeculativeDecoding2023]

| Batch size | Speedup of adaptive speculative decoding over no speculative decoding |
|---|---|
| 1 | 2.73$\times$ (63% latency reduction) |
| 32 | 1.31$\times$ |
| Average across all batch sizes | 1.94$\times$ |

All rows: [^suSynergySpeculativeDecoding2023]

### Dynamic traffic

- Client: request intervals are sampled from a Gamma distribution, which controls the average interval and the coefficient of variation (CV). CV values are 0.5, 1, 2, and 5. Interval times run from 0.1s to 0.8s in steps of 0.1s. Each sequence contains 1000 prompts, with no overlap with the profiling data.[^suSynergySpeculativeDecoding2023]
- Server: requests waiting in the queue are merged into one batched request, up to a maximal batch size of 16 because of the memory constraint.[^suSynergySpeculativeDecoding2023]
- Latency is measured from when the client sends a request to when the server finishes serving it, so queueing time is included.[^suSynergySpeculativeDecoding2023]
- Comparison points: batched inference without speculative decoding, and batched speculative decoding with fixed speculation lengths of 2 and 4.[^suSynergySpeculativeDecoding2023]

| Comparison | Result |
|---|---|
| Adaptive vs. no speculative decoding, on average | speedup of 2.3$\times$ |
| Adaptive vs. the better of the two fixed lengths, when CV is equal to 5 | additional $1.07\times$ average speedup |
| Adaptive vs. fixed speculation length, maximum | up to 1.15$\times$ |
| CV=2, request interval 0.1 | speculation length of 2 achieves the best latency among fixed lengths |
| CV=2, request interval 0.6 | speculation length of 4 achieves the best latency among fixed lengths |

All rows: [^suSynergySpeculativeDecoding2023]

Timeline experiment: the client alternates every 50 seconds between intense traffic (request interval 0.2 seconds) and sparse traffic (request interval 1 second), with CV fixed at 1. A speculation length of 4 is better for sparse traffic and 2 for intense traffic. Adaptive improves latency over speculation lengths of 2 and 4 by 9% and 14%, respectively, on average.[^suSynergySpeculativeDecoding2023]

## Limitations

- The runtime model neglects the prefilling stage and assumes equal time per iteration, which the paper says holds when the context is not extremely long.[^suSynergySpeculativeDecoding2023]
- The evaluation in Section 5 uses one model pair (OPT-6.7B with OPT-125M), one GPU (RTX 3090), and one dataset.[^suSynergySpeculativeDecoding2023]
- The algorithm is described for argmax sampling.[^suSynergySpeculativeDecoding2023]
- Batch sizes that are not powers of two are not profiled.[^suSynergySpeculativeDecoding2023]
- For each dynamic traffic setting only one sequence of requests is generated.[^suSynergySpeculativeDecoding2023]
- Speculative decoding without batching is not evaluated in the dynamic traffic experiment.[^suSynergySpeculativeDecoding2023]
- The paper has no dedicated limitations section.
